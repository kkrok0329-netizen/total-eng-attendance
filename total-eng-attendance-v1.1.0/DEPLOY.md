# 배포 준비와 운영

## 현재 상태

실행 가능한 서버·모바일 PWA·Docker·HTTPS 설정을 포함합니다. 아직 외부 서버에는 배포하지 않았으며 배포 URL도 없습니다. 실제 갤럭시와 아이폰 설치 검증은 HTTPS 배포 후 해야 합니다.

## 준비할 것

GitHub에 파일을 올리고 서버 호스팅에 연결하려면 [GITHUB_UPLOAD_GUIDE.txt](GITHUB_UPLOAD_GUIDE.txt)의 Render 경로를 사용할 수 있습니다. 저장소에는 `render.yaml`을 포함했습니다. 이 경로에서는 Render가 제공하는 HTTPS 주소를 사용하므로 별도 도메인을 구매하지 않아도 됩니다. 영구 디스크는 유료 서비스이며 아직 계정 연결·서버 생성·결제는 하지 않았습니다.

아래는 직접 준비한 서버에서 Docker Compose로 실행하는 별도 경로입니다.

1. Docker Compose를 실행할 Linux 서버 1대와 연결할 도메인.
2. 도메인의 A 레코드를 서버 주소로 설정하고 80/443 포트를 개방.
3. 회사 담당자가 확인한 개인정보 수집·이용 안내: 목적, 항목, 보유기간, 동의 거부 시 안내, 회사 문의처.
4. 관리자가 보관할 비밀번호(8자리 이상). 작업자는 회사 코드 없이 가입합니다.

## 실행

배포 ZIP을 서버의 작업 폴더에 풉니다. `.env.example`을 `.env`로 복사한 뒤 값을 설정하거나, Node.js 24에서 `npm run setup`으로 새 파일을 만드세요. 기존 데이터가 있다면 암호화 키를 새로 만들지 마세요.

`.env`의 운영 설정:

```text
NODE_ENV=production
DOMAIN=실제도메인
APP_ORIGIN=https://실제도메인
DATA_ENCRYPTION_KEY=생성된64자리16진수키
ADMIN_PASSWORD=설정할8자리이상의관리자비밀번호
PRIVACY_NOTICE="회사의 실제 개인정보 수집·이용 안내 전문"
COLLECT_RRN=false
RRN_COLLECTION_BASIS=
```

`PRIVACY_NOTICE`가 비어 있으면 가입을 차단합니다. 안내를 한 줄에 쓰거나 환경 파일이 지원하는 따옴표를 사용하세요. 주민등록번호 입력이 필요한 경우 회사가 해당 수집 근거와 운영 절차를 확인한 뒤 `COLLECT_RRN=true`와 `RRN_COLLECTION_BASIS`를 함께 설정합니다. 이 설정만으로 수집 적법성이 검증되는 것은 아닙니다.

```sh
docker compose up -d --build
docker compose ps
```

Caddy가 도메인 인증서를 발급하고 HTTPS를 제공합니다. 웹앱은 호스트에 3000 포트를 공개하지 않습니다. `https://실제도메인/healthz`가 정상인지 확인하세요.

## 휴대폰 설치와 사용

- 갤럭시: Chrome 또는 삼성 인터넷에서 링크 열기 → 설정 → 앱 설치. 브라우저가 설치 창을 제공하지 않으면 브라우저 메뉴의 앱 설치/홈 화면에 추가 사용.
- 아이폰: Safari에서 링크 열기 → 공유 → 홈 화면에 추가 → 추가.
- 카카오톡 안에서 설치가 보이지 않으면 외부 브라우저로 열기.
- 먼저 설치한 다음 작업자 등록 또는 로그인. 다른 기기에서는 동일한 생년월일 6자리와 비밀번호 4자리 사용.
- 관리자: 설정 → 관리자 모드 → `.env`에 설정한 관리자 비밀번호 → 작업자 선택 → 달력/목록 전환.
- 비밀번호를 변경할 때는 `.env`의 값을 바꾸고 `docker compose up -d --force-recreate app`으로 재시작하세요. 앱이 재시작되면 기존 관리자 인증은 모두 해제됩니다.

## 출시 전 실기기 확인

- 갤럭시 Chrome/삼성 인터넷과 아이폰 Safari에서 각각 등록·로그인·홈 화면 설치.
- 같은 계정으로 두 기기에서 날짜별 기록 조회. 저장 후 다른 기기는 화면을 다시 열어 갱신.
- 18만원 × 0.25공수 = 45,000원, × 1.25공수 = 225,000원.
- 일당 변경 시 과거 날짜 금액 유지, 신규 날짜에 새 일당 적용.
- 관리자 작업자별 목록/달력 전환, 월 이동, 개인정보 가림/전체 보기, 관리자 종료 후 접근 차단.
- 인터넷 끊김 시 저장 완료로 표시되지 않는지 확인.

## 백업과 복구

```sh
docker compose exec app node scripts/backup.mjs
```

백업은 `attendance-backups` 볼륨에 생성됩니다. 정기적으로 서버 밖의 안전한 보관소에도 복사하고, `.env`의 암호화 키는 백업 DB와 별도로 안전하게 보관하세요. 키를 잃으면 신상과 작업내용을 복구할 수 없습니다.

복구할 때는 앱을 멈추고 백업본을 데이터 볼륨의 `attendance.sqlite`로 배치한 뒤, 원래 암호화 키로 시작합니다. 서비스가 완전히 종료된 상태에서만 WAL/SHM을 포함한 DB 파일 교체를 진행하세요. 볼륨을 삭제하는 `docker compose down -v`는 사용하지 마세요.

## 범위와 한계

- 서버 한 대의 소규모 사내 운영용 구성입니다. Compose는 앱을 Caddy 뒤에서만 노출하고 `TRUST_PROXY=true`로 접속 IP를 구분합니다. 앱 포트를 인터넷에 직접 노출하거나 임의의 프록시를 추가하지 마세요. 로그인 제한에 걸리면 15분 후 재시도합니다.
- 암호화해도 서버 관리자는 복호화 키에 접근할 수 있으므로 서버 접근 권한과 키 보관은 별도로 관리합니다.
- 사용자 비밀번호 초기화·신상 수정·탈퇴·보유기간 만료 삭제는 아직 앱 화면에 없습니다. 실제 운영 절차와 기능을 정한 뒤 실데이터 운영을 시작하세요.
- Excel/Google Sheets 자동 연동, SMS 본인확인, 급여 지급과 세금 신고는 포함하지 않았습니다.
- 앱스토어/플레이스토어 심사를 거치는 네이티브 앱은 아닙니다. 설치 가능한 모바일 웹앱입니다.

설치 조건과 플랫폼별 차이는 [MDN PWA 설치 안내](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)를 참고하세요.
